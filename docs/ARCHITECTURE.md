# 应用结构

前端按职责收敛为五个运行模块，题库与样式独立维护。

## `js/core/app.js`
只负责应用基础：状态、路由、通用工具、渲染入口和生命周期。它不实现双人网络、历史数据库或 PWA。

## `js/features/quiz-flow.js`
只负责问卷流程：25 题题组、作答进度、完成判定、重新作答、双方开始下一题组的协调。

## `js/core/duo.js`
只负责双人房间：房间码、MQTT、端到端加密、在线状态、断线重连、双方状态交换。

## `js/features/history.js`
只负责完成记录：本机历史、Supabase 云备份、上传状态、手动上传、去重、删除、历史页面和 Word 导出。`历史记录` 是唯一名称。

## `js/core/shell.js`
只负责外围 UI：首页文案、设置、安装/刷新入口及低频页面壳层。

## 约束
- 一个公共函数只能有一个所有者和一个定义位置。
- 禁止 `const baseX=x; x=function(){...}` 这类运行时补丁链。
- 禁止新增 `*-fix.js`、`*-patch.js`。
- 模块通过公开对象通信，不互相覆盖函数。
- 题库继续保存在 `banks/`；当前实时状态继续走 EMQX；只有完成的历史记录进入 Supabase。
- 统一术语：`历史记录`、`双人房间`、`题组`、`上传`、`已上传云端 / 待上传 / 上传失败 / 仅本机`、`慢慢真心话`。

## CI
`scripts/check-architecture.js` 阻止补丁式覆盖、旧名称回流，以及 index 重新加载废弃补丁文件。后续修改直接进入上述职责文件。
